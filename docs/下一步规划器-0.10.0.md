# 下一步规划器（0.10.0）

## 目标

0.8 让研究程序可记录，0.9 让文献可检索，但“现在下一步调用什么”仍由 agent 从闸门清单里自行推断。0.10 把这一步变成确定性计划：读取当前阶段、闸门与程序缺口，返回一个主推荐工具调用与少量备选，并明确哪些动作需要人、哪些情况必须停。

它解决的是**控制层**问题，不是模型能力问题。规划器不判断科学价值、不替人写假设、不自动批准发布；它只把已经失败或即将失败的检查映射到具体工具调用。

## 接口

```json
{
  "action": "next",
  "campaign": "rs-…"
}
```

返回：

```json
{
  "ok": true,
  "plan": {
    "stage": "survey",
    "gateOk": false,
    "blocking": ["min_sources", "primary_sources"],
    "programMissing": ["plan_objective"],
    "primary": {
      "tool": "rsx_search",
      "args": { "query": "…", "limit": 10, "provider": "both" },
      "label": "检索候选文献",
      "why": "survey needs 8 sources (currently 0)…",
      "unblocks": ["min_sources", "primary_sources", "recent_source"],
      "needsInput": false,
      "human": false,
      "risk": "low",
      "followUps": [{ "tool": "rsx_source", "args": { "action": "add" }, "note": "register only inspected candidates" }]
    },
    "steps": [],
    "stop": { "ready": false, "blocked": false, "escalate": false, "code": null, "reason": "" },
    "budget": { "ratio": 0, "overruns": [] },
    "policy": { "maxCycles": 4 }
  },
  "gate": {},
  "integrity": {}
}
```

`primary` 是 `steps[0]`；`steps` 最多 8 条。每条都带 `tool` 和可直接传给该工具的参数；占位参数保持 `<…>` 形式并标记 `needsInput:true`，避免把模板当成真实证据。

## 排序与映射

排序规则：

1. 先 `priority`（当前都相同，保留扩展位）；
2. 同优先级时 `gate` 阶段先于 `program` 阶段；
3. 同一工具+参数去重；
4. 截断到 8 条。

阶段映射按当前失败检查逐条生成，不按“阶段模板”整段输出：

| 检查/缺口 | 主推荐 |
| --- | --- |
| `question` / `scope` / `success` | `rsx_campaign action:"update"`，标 `needsInput` |
| `world_question` | `rsx_campaign action:"world"`；已有研究问题时直接填入，`needsInput:false` |
| `min_sources` / `primary_sources` / `recent_source` | `rsx_search`；`followUps` 提示只登记实际读过的候选 |
| `content_captured` | `rsx_source action:"update" path:<captured file>` |
| `disconfirming_search` / `search_protocol` | `rsx_campaign action:"search"` / `"searchLog"` |
| `coverage_map` | `rsx_campaign action:"world" kind:"coverage"` |
| `source_independence` / `source_rob` | `rsx_source action:"update"` |
| `hypothesis` / `falsifier` / `kill_criterion` / `metric` | `rsx_claim action:"add"` 或 `"update"` |
| `support` / `novelty` | `rsx_evidence` / `rsx_campaign action:"world" kind:"novelty"` |
| `prereg*` / `negative_control` / `env_lock` / `prereg_lock` | `rsx_campaign action:"prereg"`，保留已有字段 |
| `success_run` / `seed` / `metrics` / `negative_control_run` | `rsx_run action:"record"` |
| `run_stdout` | `rsx_run action:"attach"` |
| `numbers_present` / `trace_*` / `uncertainty` | `rsx_number action:"add"` |
| `claims_resolved` / `claim_*` / `sensitivity*` | `rsx_claim` 对应动作 |
| `manuscript` / `number_refs` / `cite_refs` / `no_orphan_numbers` | `rsx_write action:"manuscript"` |
| `figure_provenance` | `rsx_figure action:"add"` |
| `automated_audit` | `rsx_review action:"audit"` |
| `two_reviews` / `adversarial_review` / `no_reject` | `rsx_gate action:"review"` |
| `program_complete` | 展开 `programComplete()` 的具体缺口：plan/perspective/autonomy/cycle/match/quality/contradiction |
| `declaration*` / `dual_use` / `human_approval` / `ai_contribution` | `rsx_write action:"declaration"` / `rsx_campaign action:"world"` / `rsx_gate action:"approve"`；标 `human:true` |
| `upstream_gates` | `rsx_gate action:"history"`，提示回到失败阶段 |
| `chain_integrity` / `budget` | 停止并检查；不产生可执行后续 |
| 未映射 | `rsx_gate action:"check"`，不编造修复 |

`program` 步骤从 survey 阶段开始并行出现；它们不是当前闸门的阻断项，但会阻止 review 的 `program_complete`。review 阶段则把缺口直接展开到 `steps`。

## 停止规则

`stop` 在生成步骤前计算，优先级如下：

1. 完整性失败：`chainOk === false`、`stateOk === false` 或存在工件问题 → `code:"integrity"`，`escalate:true`；
2. 预注册晚于首次运行 → `code:"prereg_timing"`，`escalate:true`。这不是可修复的时间戳问题，不能靠改记录绕过；
3. 预算超限 → `code:"budget"`，`escalate:true`；
4. 发布闸门通过 → `code:"released"`，`ready:true`，给导出与交给人复核；
5. 最新循环 `stop` / `escalate` → `cycle_stop` / `cycle_escalate`；
6. 循环数达到 `maxCycles` → `cycle_budget`，`escalate:true`。

发布优先于终止循环，是因为一个已完成项目的最后一次 `stop` 是正常终点，不是未完成阻断。这个顺序由真实宿主调用发现：0.8 验收项目 `rs-f7edf967` 的 `K-0001` 决策为 `stop`，旧顺序把它误报为停止；修复后同一调用返回 `可交付 / export`，并新增回归用例。

## 人类检查点

规划器只标记，不代签：

- `dual_use`：双重用途审查；
- `human_approval`：发布批准；
- `declaration` / `ai_contribution`：AI 参与声明与贡献矩阵；
- `prereg_timing` / `budget` / `integrity`：停止并升级。

这些步骤的 `human:true` 会显示在面板的“人工”徽章与返回 JSON 中。自动批准、自动豁免、自动改写预注册都不在实现里。

## 与外部工作的关系

结构参考：Anthropic 的 orchestrator-worker 与“分解—委派—核验引用”、Google Co-Scientist 的 generate→debate→evolve 与锦标赛、Kosmos 的世界模型与下一问题循环、STORM 的多视角提问、PaperQA2 的矛盾优先审查、AI Scientist-v2 的实验→评审循环。这里只借用控制结构；没有复现它们的模型、检索或实验，也不引用其效果量作为本实现的证据。

## 测试

`test/unit/planner.test.mjs` 11 个用例：

1. 新项目只差 `world_question`，主推荐 `rsx_campaign action:"world"`，直接使用已记录问题；
2. 测绘阶段主推荐 `rsx_search`，不是来源模板；
3. 假设阶段推荐完整 `rsx_claim`（falsifier / kill criterion / 指标）；
4. review 阶段展开 `program_complete` 的具体 `rsx_program` 调用；
5. 已发布项目返回 `ready + export`；
6. 发布闸门通过优先于终止循环；
7. 预算超限停止；
8. 完整性失败停止并升级；
9. `stop` / `escalate` / `maxCycles` 三种循环停止；
10. 预注册晚于数据停止；
11. 非法输入拒绝。

全量 **133/133** 通过（`npm test`，约 10.0 s）；`npm run check` 通过，client 6 fragments / 107,805 B。

## 真实验收

- 工具层：`_artifacts/real-0.10/run-planner.mjs` 通过真实 `rsx_campaign` handler 在临时库调用 `next`；定题主推荐 world，测绘主推荐 search；连续 `next` 前后事件数 `1 → 1`。
- 宿主 0.10.0：`rs-79d63da4` 定题（`world_question`）、`rs-7bcc3f06` 测绘（`rsx_search`）、`rs-f7edf967` 发布（`gateOk:true`、12/12、`ready:true`、export）。三次均返回完整 gate 与 integrity，未写台账。
- 面板：DSH 侧边栏显示 `科研套件 / 0.10.0`；总览“下一步 / 可交付 / 导出研究包”；复制按钮变为“已复制到剪贴板”。截图 `panel-next-1440.png`、`panel-next-copied-1440.png`、`panel-next-390.png`。
- 固定开销：**11,537 cl100k / 11,505 o200k**（16 schemas + prompt），相对 0.9 增加 **115/115**（约 +1.0%）。

## 边界

- 不执行推荐：没有模型调用、没有网络请求、没有自动写证据；`next` 本身只读。
- 不自动登记候选：检索结果只是候选，必须检查后 `rsx_source`；`followUps` 明确这一点。
- 不自动批准：`human:true` 的步骤不能由规划器完成。
- 映射表是人工维护的：闸门新增检查后，规划器可能落到 `rsx_gate action:"check"`；这是可见的降级，不是静默猜测。
- 没有检索质量估计、跨项目调度、自动 waiver、重试/退避。
- 真实验收用的是宿主已有项目与临时库；没有新建真实研究，也没有把规划器的建议当成科学结论。
