# 参考文献互操作（0.13.0）

0.13 的起点不是“再加一个导出格式”，而是一次针对真实研究工具链的对照：研究者已经在 Zotero / EndNote / Rayyan 里积累了题录，套件若只收 BibTeX，第一步就要手工转换；而投稿时需要的是可被文献管理器、Pandoc/Quarto 和期刊系统直接消费的引用文件，以及一张能看出“哪些台账来源真的被手稿引用”的参考文献表。

## 调研对照

| 工具/标准 | 实际交换面 | 对套件的含义 |
| --- | --- | --- |
| Zotero | CSL-JSON、RIS、BibTeX 均可导出；CSL-JSON 保留 Zotero 字段最完整 | CSL-JSON 应作为首选导入格式，而不是让用户先转 BibTeX |
| EndNote / Rayyan / 多数图书馆目录 | RIS（`TY/AU/TI/JO/PY/DO/UR/AB/ER`） | RIS 需要容忍多记录、续行和缺失字段 |
| CSL 1.0.2 | 条目类型、作者/日期/容器变量、`citation-key` | 只做数据交换，不实现 CSL 样式引擎；类型映射必须保守 |
| Crossref REST API | `GET /works/{doi}` 返回单条作品元数据 | 已知 DOI 的精查应独立于关键词检索，且要拒绝 DOI 不一致的响应 |
| PRISMA 2020 | 识别/筛选/纳入的数量与排除理由 | 0.13 只做引用覆盖；候选级筛选台账留到 0.14 |
| CRediT（ANSI/NISO Z39.104-2022） | 14 类贡献角色 | 0.13 不伪造作者贡献；留到 0.15 的投稿包 |
| RO-Crate 1.1 | 研究对象与文件、来源的 JSON-LD 图 | 现有 `ro-crate-metadata.json` 继续作为溯源层；引用文件是导出附件，不重复造图 |

结论：**先补“题录进出 + 引用表”这一层，收益最大、风险最小**。它不改变九道闸门、不引入全文解析，也不把套件变成文献管理器。候选级筛选、投稿元数据和 CRediT 是后续层，不能在 0.13 里用“看起来完整”的字段假装完成。

## 0.13 的实现

### 1. 三种格式，一个入口

`rsx_source action:"import"`：

```json
{
  "campaign": "rs-...",
  "action": "import",
  "format": "auto",
  "data": "[{\"type\":\"article-journal\",\"title\":\"…\",\"DOI\":\"10.…\"}]"
}
```

- `format:"auto"` 按内容探测：`[`/`{` → CSL-JSON，`TY  -`/`ER  -` → RIS，`@type{` → BibTeX；也可显式指定。
- CSL-JSON 支持顶层数组和 Zotero 的 `{"items":[…]}`；RIS 支持多记录与字段续行。
- 单字段截断、HTML 剥离、最多 100 条；未知 CSL/RIS 类型映射为 `other`，不推断成 `paper`。
- DOI 优先去重；无 DOI 时按规范化标题去重。重复项进入 `skipped`，不静默丢弃。
- 旧 `sourceImportBibtex` 保留，`action:"import"` 对 BibTeX 仍走原解析器与 100 条上限。

### 2. DOI 精查

`rsx_source action:"lookup" {doi:"10.1234/abc"}`：

- 只查 Crossref 单条记录，不把 DOI 当关键词再搜一遍。
- 校验规范 DOI 形状；Crossref 返回的 DOI 与请求不一致时失败，不把别的作品写进台账。
- 404 映射为 `not_found`；成功时返回 `candidate` 与 `sourceDraft`，`sourceDraft` 可直接展开为 `action:"add"` 的参数。
- 不写状态。是否登记由调用者决定，避免“查了一下就多一条来源”。

### 3. 导出与报告

- 导出目录新增 `references.csl.json`、`references.ris`，与 `references.bib` 一起进入 `BUNDLE.zip`、`paths` 和 `REPORT.md` §17.1。
- 三种格式共用 `makeBibKey`，同一台账的 citation key 一致且唯一（重复作者/年份时追加 `a/b/…`）。
- `REPORT.md` §17 生成作者—年份—标题—期刊/出版社—DOI/URL 的参考文献表；从手稿 `[[src:S-0001]]` 解析引用覆盖，未引用来源保留并标注“（手稿未引用）”。没有手稿时不制造“未引用”噪音。
- 面板审查视图新增 CSL-JSON/RIS 下载；`GET /api/references/:id?format=csl-json|ris` 与 `/api/bibtex/:id?format=…` 返回同一渲染结果。

### 4. 类型映射

| 台账 `kind` | CSL type | RIS type |
| --- | --- | --- |
| `paper`（有期刊） | `article-journal` | `JOUR` |
| `paper`（无期刊） | `article` | `JOUR` |
| `preprint` | `article` + `genre:"preprint"` | `UNPB` |
| `book` | `book` | `BOOK` |
| `report` | `report` | `RPRT` |
| `dataset` | `dataset` | `DATA` |
| `registry` | `report` | `RPRT` |
| `news` | `webpage` | `NEWS` |
| `other` | `document` | `GEN` |

RIS 的 `TY  - JOUR` 在没有期刊字段时仍保留“论文”语义；CSL 的 `article` 与 `article-journal` 都映射回 `paper`。这种不对称是格式本身的历史差异，文档里明确写出，不在代码里偷偷修正。

## 仍未做（按优先级）

1. **0.14 候选级筛选与 PRISMA 流水**：每条候选的 title/abstract/full-text 决策、排除理由、重复计数、PRISMA 流程图数据，不再只有 `hits/screened/included` 三个聚合数。这是从“检索协议”走到“可审计系统综述”的关键一步。
2. **0.15 投稿包**：CRediT 14 角色、资助/利益冲突、数据/代码可用性、伦理/注册号、PRISMA/CONSORT/TRIPOD+AI 的逐项清单。当前的领域标准还是文本字段，不能声称“符合 PRISMA”。
3. **0.16 可选全文层**：只有在外部解析器存在时才做页锚定抽取；不把 PDF 解析器打进插件，也不把解析结果当原文。
4. **不做**：替用户执行实验/统计、自动批准、分布式多人协作、替期刊渲染特定期刊样式。CSL-JSON/RIS 是交换格式，不是 CSL 处理器。
