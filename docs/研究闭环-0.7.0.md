# 研究闭环 0.7.0：把“查过了”变成可复核的检索与稳健性

0.6 解决的是“证据为什么支持结论”。0.7 继续补两个长期被一句“已检索/结果稳健”带过的缺口：**检索过程**与**换设定后的结论**。同时把“预注册在运行之前”从时间戳提示升级为可失败检查，并给词面证据筛查加上否定与数字极性。

## 1. 范围

| 能力 | 数据 | 工具入口 | 阻断位置 |
| --- | --- | --- | --- |
| 检索协议 | `searchLog: Q-0001…` | `rsx_campaign action:"searchLog"`；`action:"search"` 仍保留否证检索快捷入口 | schema 3 的 survey `search_protocol` |
| 敏感性/稳健性 | `sensitivity: Z-0001…` | `rsx_claim action:"sensitivity"` | schema 3 的 analyze `sensitivity` / `sensitivity_traces` |
| 预注册时序 | `prereg.lockedAt` vs 最早 `runs[].ts` | 无需新动作，沿用 `action:"prereg"` | schema 3 的 execute `prereg_before_run` |
| 引文极性筛查 | `checkEntailment().flagged` | `rsx_review action:"entailment"` | 审计 `claim_evidence_negation`（major）/ `claim_evidence_number`（minor） |

## 2. 检索协议

一条记录回答：在哪个库、用什么查询、覆盖什么日期、命中多少、初筛多少、纳入多少、是否否证检索。

```json
{
  "id": "Q-0001",
  "kind": "database",
  "database": "PubMed",
  "query": "enzyme temperature kinetics",
  "dateFrom": "2015-01-01",
  "dateTo": "2025-12-31",
  "hits": 120,
  "screened": 40,
  "included": 8,
  "disconfirming": false,
  "notes": "去重后 40 条；排除非体外体系",
  "at": "2026-11-18T00:00:00.000Z"
}
```

校验：`query` 至少 3 字符；`hits >= screened >= included >= 0`；日期范围不得反向。计数可以缺省（例如滚雪球检索没有“命中数”），但审计会把它列为 minor `search_counts_missing`，survey 闸门只要求至少一条可复核查询。`action:"search"` 仍写入 `state.search` 以兼容 release 的否证检索检查，同时自动生成一条 `kind:"disconfirming"` 的 `Q-` 记录。

导出新增 `SEARCH.md`，报告新增 `3.1 检索协议`，评审包新增检索表。

## 3. 敏感性分析

一条记录只描述一次刻意改变：改模型、改子样本、改阈值、改结果口径、留一法、负对照。`direction` 是分析者对本次结果的分类，不是对真实效应的裁决。

```json
{
  "id": "Z-0001",
  "claim": "C-0001",
  "name": "leave-one-batch-out",
  "method": "leave-one-out",
  "specification": "逐批剔除一个批次后重估主效应",
  "result": "r 仍在 0.41–0.46，方向不变",
  "direction": "consistent",
  "trace": "run:R-1a2b3c4d5e#pearson_r",
  "notes": "批次 3 影响最大，但未改变方向"
}
```

`name`、`method`、`specification`、`result`、`direction` 必填；`trace` 可选，但给了就必须能解析为 `run:R-… #metric` 或 `source:S-…`。analyze 闸门要求至少一条记录；审计对“无记录”“字段不合法”“trace 解析失败”分别报 major，对“只有叙述、没有 trace”报 minor。

导出新增 `SENSITIVITY.md`，报告新增 `4.1 敏感性分析`，评审包新增稳健性表。

## 4. 预注册时序

`prereg.lockedAt` 是首次锁定时间。execute 闸门比较它与最早的 `runs[].ts`：运行早于锁定，`prereg_before_run` 阻断（schema 3）；没有锁定时由 design 闸门负责，不在 execute 重复报错。审计对同样情况报 `prereg_after_run`（major）。

边界：时间来自本机时钟与调用者写入的 ISO 时间，不是可信时间戳服务；它能抓“先跑后补”，不能证明锁定的绝对时刻。

## 5. 引文极性

词面覆盖仍不是语义蕴含。0.7 增加两类便宜的失败信号：

- **否定极性**：断言与引文一个含否定词、另一个不含，词面再像也标 `weak`，审计 `claim_evidence_negation`（major）。
- **数字不一致**：断言里的数字与引文没有任何交集，标 `number_mismatch`，审计 `claim_evidence_number`（minor）。数字仍应以 `N-` 台账为准。

这两类信号只用于把人工复核引到正确位置，不自动判定引文无效。

## 6. schema 与兼容

- `SCHEMA_VERSION = 3`：新建项目。
- `CORE_SCHEMA = 2`：0.6 的严谨性检查对 schema 2+ 继续阻断。
- 0.7 新检查对 schema 3 阻断；对 schema 1/2 是 advisory（审计仍可报，但不改已发布项目的闸门结果）。
- `auditSubject` 只在 `searchLog` / `sensitivity` 非空时纳入新字段，并升级 subject version 到 2；旧项目对象哈希不变，A-0004 等既有审计不会因为升级无故失效。

## 7. 不做的事

- 不代跑数据库检索，不解析 PDF，不声称 PRISMA 合规。
- 不自动生成“稳健”结论；方向由分析者填写并接受评审。
- 不把词面筛查当语义模型；否定/数字规则是启发式，可能漏报与误报。
- 不用本机时间戳冒充可信时间源。
