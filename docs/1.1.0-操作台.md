# 1.1.0 操作台：跨项目组合与可恢复归档

1.0 把单个研究项目的契约做完整了，但没有回答“项目多起来之后，先看哪一个”。同时，旧动作门把归档和导出绑在同一组条件上：一个在定题阶段卡住的项目，既不能导出，也不能收尾；一个暂停中的项目，连归档都做不到。1.1 只改运营层，不动九道闸门、schema 与工具数量。

## 1. 组合视图

服务端新增 `GET /api/portfolio`，复用已有的 `service.portfolio()`，但补了面向操作者的字段：

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `releasePassed` | 最新一条 release 闸门记录是否 `ok` | `state.gates` 中 `stage:"release"` 的最后一条 |
| `attention` | 是否存在需要人处理的状态 | 下列原因之一 |
| `attentionReasons` | `stale_audit / audit_blocking / monitoring_alert / integrity / schema` | 审计对象哈希、审计阻断数、监测告警、完整性、schema |
| `schema` | 当前 schema | `state.schema`，旧项目按 1 计 |
| `audit` | 最新审计的 verdict、blocking、major、fresh | `state.audits` 最后一条 |
| `integrity` | `chainOk / stateOk / brokenSeq` | `store.verify()` |
| `totals` | `campaigns / released / l4 / withAlerts / staleAudits / brokenIntegrity / unmigrated / attention / archived` | 服务端一次计算 |

`totals.released` 不再用 `stage === "release"` 计数。处于发布阶段但闸门没过的项目不是“已发布”，它会计入进行中。这是 1.1 修掉的一个语义错误。

面板新增 **组合** 标签：

- KPI：进行中 / 已发布 / 需关注 / 归档项目。
- 搜索：标题、ID、领域、阶段；不区分大小写。
- 筛选：全部 / 需关注 / 进行中 / 已发布；筛选计数来自服务端 totals 或当前行集。
- 排序：需关注优先，其次按 `updatedAt` 倒序；不额外维护一份评分。
- 每行：项目标题与 ID、领域、阶段、闭环分、审计、完整性、告警数、更新时间、打开。
- 打开行会调用 `selectCampaign`，回到总览并加载该项目的详情与领域信息。

## 2. 归档状态机

归档是**生命周期动作**，不是交付动作。1.1 的规则：

| 动作 | 允许条件 | 拒绝原因 |
| --- | --- | --- |
| `archive` | 未归档、没有写锁 | `archived` / `busy` |
| `unarchive` | 已归档、没有写锁 | `busy`；未归档时幂等返回 `changed:false` |
| `export` | release 闸门通过、无开放暂停、未归档、没有写锁 | `release` / `paused` / `archived` / `busy` |

实现点：

- `lib/ledger.js` 新增 `unarchive(id)`：把 `archived` 置回 `false`，写 `campaign.unarchived`，保留完整事件链；只有当前没有活跃项目、或当前就是该项目时才把它设为 current，避免恢复动作抢走操作者的选择。
- `service.actionGate(campaign, 'archive')` 不再计算 release 闸门，也不检查暂停；`export` 保持原来的发布/暂停门。
- `service.unarchive()` 在写锁存在时返回 `action_blocked`，与其他动作一致。
- `service.state()` 返回 `archivedCampaigns` 与 `archivedCount`；归档项目不出现在活跃 `campaigns` 里，但保留在索引与磁盘上。
- HTTP：`POST /api/campaign {action:"unarchive", campaign}`；工具：`rsx_campaign action:"unarchive"`。
- 面板：头部显示归档数量；弹窗列出标题、ID、阶段、更新时间与恢复按钮；恢复后关闭弹窗、回到总览并加载该项目。

暂停中的项目可以归档，暂停记录不清除；恢复后仍然能看到 `LP-xxxx` 和 `loop.paused`。这保证“收尾”不会篡改待处理的审计状态。

## 3. 错误、竞态与可访问性

- `apiGet` / `apiPost` 统一构造带 `code`、`status`、`detail` 的 Error；面板用 `errorText()` 显示 `[code] message`，不再只给一句英文。
- 项目切换、刷新、详情、领域请求各有序列号；旧响应不会覆盖新选择。刷新按钮的旋转状态也只由最后一次请求关闭。
- 模态框：打开时记住焦点并聚焦第一个可操作元素；Tab / Shift-Tab 在框内循环；Escape 关闭；关闭后把焦点还给触发元素；打开期间不会因父组件重渲染反复重置焦点。
- 健康表的问题单元格改为 `<details>`：`E0 W0 I1` 摘要，展开后列出 severity、code、detail 与 ref。
- 导航不再强制换行，窄屏横向滚动；按钮、输入、`[tabindex]` 有 `:focus-visible`；`prefers-reduced-motion` 下关闭旋转和过渡。

## 4. 删除无效配置

1.0 的设置面板有一个“允许 rsx_run 直接执行命令”的开关，但 `rsx_run` 从实现上只是登记一次已捕获的运行记录，没有任何命令执行路径。1.1 删除这个开关、`DEFAULT_SETTINGS.allowExec` 与 `resolveConfig().allowExec`；旧 `settings.json` 里的键在 `settings()` 与 `saveSettings()` 中被忽略并清理。工具说明继续明确“record-only”。

## 5. 兼容与非目标

- 仍是 16 个工具、schema 5、九道闸门；新增 1 个 `rsx_campaign` action，不新增工具。
- schema 1–4、旧归档项目、旧 settings 文件继续可读。
- 组合视图是只读的；不在面板里提供批量迁移、批量归档或批量导出。每个写动作仍然逐个项目走显式确认与闸门。
- 归档不是删除；不提供物理删除、压缩归档目录或跨设备同步。
- 组合的 `attention` 是操作提示，不是学术质量评分；它不替代 release 闸门。
