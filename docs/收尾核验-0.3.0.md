## 4. 兼容性与迁移

- `provenance.json` 的 `format` 从 `dsh-research-suite/provenance/1` 变为 `dsh-research-suite/prov-json/1`，旧消费者需改为读 PROV-JSON 的 `entity/activity/agent` 与关系表。
- 0.2 期间产生的审查没有 `signature`/`stateHash`：`integrity.stateOk` 返回 `null`，`auditList` 标记 `unsigned`；review 闸门要求最新审查签名，因此旧项目需重跑一次 `rsx_review audit`。真实项目中的 `A-0001` 正是这个迁移样本。
- 旧 `state.json` 没有 `stateHash`：下一次 `save`/`emit` 自动补齐；补齐前按链校验，不误报篡改。

## 5. 遗留风险

| 风险 | 现状 | 下一步 |
| --- | --- | --- |
| 审查签名是本地 HMAC | 挡改 findings 后重算哈希；挡不住同时拥有数据目录与密钥的本地攻击者 | 外部 KMS / 时间戳 / 透明日志 |
| `stateHash` 未加盐、未签名 | 发现意外修改与不一致，不提供不可否认性 | 由审查签名覆盖 subject/state 锚点，或改为 HMAC state digest |
| 写锁是本地文件锁 | 单共享目录有效；NFS/SMB 语义不承诺 | 需要时加租约/数据库事务 |
| 单 fd 读仍非绝对 TOCTOU-free | 已校验 inode/size/内容哈希；内核层同 inode 竞争无法完全排除 | 关键场景复制到独立快照后再读 |
| PROV-JSON 是核心子集 | 未覆盖 `wasInformedBy`、角色限定、完整 PROV-O 约束 | 需要时接 PROV 校验器 |
| 无文献检索/PDF 解析 | 边界未变 | 由 agent/MCP 完成检索与抽取 |
