## 2. 本轮补齐的缺口

| # | 缺口 | 修复 | 回归断言 |
| --- | --- | --- | --- |
| 1 | 来源 `contentHash` 指向不存在的工件时审查不报错 | `checkSources` 新增 blocking `source_content_missing` | 篡改来源 hash，断言 blocking |
| 2 | 合法 `sha256:` 证据引用被误判为 `evidence_ref_invalid` | `checkEvidence` 区分 source / run / artifact，新增 `evidence_artifact_missing` | 合法工件引用不误报；改成不存在 hash 后 blocking |
| 3 | 两个来源请求同一显式 BibTeX key 会生成重复 key | `makeBibKey` 对显式 key 也走唯一化后缀 | 两条 `same` key 断言不相等 |
| 4 | 导出写在 `note` 的 kind 不能导回 dataset/report/preprint | `sourceFromBibEntry` 解析 `note = {kind: …}` | dataset 往返后 kind 保持 |
| 5 | 矩阵表头/标题含 `\|` 或换行会破坏 Markdown；缺 `cells` 会崩 | 统一 `tableCell` 转义 + `cells || {}` | 特殊字符与空 cells 断言 |
| 6 | RO-Crate 软件版本硬编码、图里没有 claims/evidence/extraction | 引入 `VERSION`；新增 `Assertion`/`CreativeWork`/`PropertyValue` 节点并挂到 root `hasPart` | graph 节点、动态版本、root hasPart 断言 |

测试数量保持 **53**：全部为在既有测试用例内追加断言，没有新增 `test()` 块。

## 4. 遗留风险与不做的部分

| 风险 | 影响 | 现状 / 下一步 |
| --- | --- | --- |
| `provenance.json` 不是完整 W3C PROV-O/PROV-JSON | 严格 PROV 互操作工具不能直接消费 | 已改称“PROV 风格”；严格场景走 RO-Crate 1.1；后续可加 PROV-JSON 序列化 |
| RO-Crate 图没有 figure→source 的单独边 | 图与来源关系靠 `figure.source` 字段，不在 RDF 图中 | 可在 0.3 增加 `about`/`isBasedOn` 边 |
| 审查是内容哈希，不是签名 | 能检测编辑，不能防恶意重算哈希 | 需要外部签名/时间戳/透明日志才算 trust root |
| `state.json` 不参与事件哈希 | 直接改 state 后重算事件仍可能绕过 | 事件链保护的是事件日志；state 是物化视图，依赖 `verify()` 对账 |
| 工件 `stat`→`read` 的 TOCTOU | 极端并发下可能读到变化内容 | 单写者场景可接受；需要时加读锁/副本读 |
| 没有跨进程写锁 | 多个 agent 同时写同一项目可能丢更新 | 当前按单会话串行使用；后续加锁文件或乐观并发 |
| 没有内置文献检索/PDF 解析 | BibTeX 是导入解析，不是检索 | 明确边界；检索由 agent 或现有 MCP 完成 |
| 演示数据是合成队列 | 不是睡眠科学结论 | 已在 README 标注 |
