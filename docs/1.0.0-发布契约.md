# dsh-research-suite 1.0.0：发布契约

1.0 不是“再加一个功能”，而是把此前十四个版本的实验性接口收敛成一份可依赖的契约：哪些东西在 1.x 内保持稳定、哪些变化必须显式迁移、哪些失败必须阻断发布，以及发布包到底能证明什么。本文是这份契约的入口；具体迁移步骤见[迁移与恢复](1.0.0-迁移与恢复.md)，验收证据见根目录 README 的「1.0.0 验收」小节。

## 1. 稳定面

| 面 | 1.0 契约 | 向后兼容规则 |
| --- | --- | --- |
| 工具 | 16 个 `rsx_*` 工具，名称与职责不变 | 1.x 不新增第 17 个常驻工具；新能力优先扩展已有 action/字段 |
| 数据 | `state.schema = 5`；事件链 + 物化 `state.json` + 内容寻址工件 | schema 1–4 继续可读；新检查对旧 schema 只作 advisory，除非显式迁移 |
| API | 面板 HTTP API `apiVersion: 1`，回环地址，固定请求头 | 1.x 只增加字段，不删除或重命名既有响应字段 |
| 闸门 | 九道阶段闸门，稳定错误码 | 新增强制检查只对采纳该 schema 的项目生效 |
| 导出 | `REPORT.md`、`campaign.json`、`ledger.jsonl`、`BUNDLE.zip` 等既有文件 | 1.x 只增加文件，不改变既有文件的核心格式；新增 `MANIFEST.json`、`STEWARDSHIP.md` |
| 身份 | 本地数据目录、单安装审计 HMAC 密钥 | 密钥不导出、不轮换；损坏时 fail-closed |
| 依赖 | Node 22 ESM，零运行时依赖 | 1.x 不引入 native addon 或网络运行时依赖 |

`state.version = 1` 是物化状态格式版本，`state.schema` 是研究契约版本，`apiVersion` 是 HTTP 接口版本，`VERSION` 是插件版本。四者不是同一个东西；迁移只改 `state.schema`。

## 2. schema 5：FAIR / CRediT 治理

新建项目默认 schema 5。`state.stewardship` 记录：

```json
{
  "license": "CC-BY-4.0",
  "licenseUrl": "https://creativecommons.org/licenses/by/4.0/",
  "dataAvailability": "脱敏数据与导出包随论文附录提供。",
  "codeAvailability": "分析代码在仓库内，Node 22 可重跑。",
  "funding": ["基金编号"],
  "competingInterests": "无。",
  "ethics": "不涉及人类受试者；动物实验批件见附录。",
  "keywords": ["可复现研究", "证据台账"],
  "contributors": [
    {
      "name": "YG",
      "roles": ["conceptualization", "supervision", "writing-review-editing"],
      "orcid": "0000-0002-1825-0097",
      "affiliation": "Independent"
    }
  ]
}
```

- `license`、`dataAvailability`、`codeAvailability`、`competingInterests`、`ethics`、至少一名带角色的贡献者是发布必需项。
- 贡献者角色使用 CRediT 的 14 个标准角色，不接受自由文本角色；ORCID 接受裸 iD 或 `https://orcid.org/...`，存储为裸 iD。
- `funding`、`keywords`、`licenseUrl` 可选；`keywords` 去重，最多 20 个；贡献者最多 50 人。
- 治理字段在审计对象哈希之外：补治理声明不会让已完成的自动化审查过期；但 schema 5 的发布闸门会读取它，缺项时 `stewardship` 阻断。
- 这不是法律合规声明。字段齐全只表示“研究包把复用条件写清楚了”，不表示机构或法务已批准。

## 3. 发布闸门新增检查

schema 5 的 `release` 闸门在原有 12 项检查上增加 `stewardship`，共 13 项。它和 `declaration`、`human_approval` 一样是受保护检查，不能被 waiver 静默关闭。

| 检查 | 何时阻断 | 旧项目 |
| --- | --- | --- |
| `stewardship` | schema ≥ 5 且 FAIR/CRediT 必需项不完整 | schema 1–4 显示为 advisory，不改变已发布状态 |
| `chain_integrity` | 事件链、state 哈希或工件校验失败 | 仍然阻断，和 0.14 相同 |
| `human_approval` | 没有当前对象哈希上的人工批准 | 仍然阻断 |
| `automated_audit` | 最新审计过期、未签名或签名不匹配 | 仍然阻断 |

审计额外产生 `stewardship_incomplete`（major）以便评审者看到缺口；它本身不是 blocking，发布由闸门负责。`doctor` 对 schema 5、已到发布阶段但治理不完整的项目给 warning，不自动改写数据。

## 4. 生命周期：体检、迁移、重建

```text
doctor (read-only)
  ├─ chain / state hash / artifacts
  ├─ index.json vs campaigns/
  ├─ write lock age
  ├─ audit freshness + HMAC
  ├─ schema vs SCHEMA_VERSION
  └─ stewardship completeness (schema 5 only)
        │
        ├─ reindex  → 只重建 index.json
        └─ migrate  → verify → backup → schema 5 → campaign.migrated → save
```

- `doctor` 不写文件、不创建密钥、不修复。它最多读取 `LIMITS.maxDoctorCampaigns` 个项目，超出时标记 `doctor_bounded`。
- `migrate` 先验证链、state 哈希与全部工件；任何一项失败就抛 `integrity_blocked`，不写备份、不改 schema。
- `migrate` 在改契约前写 `backups/<campaign>/backup-*.zip`，内含 `manifest.json`、`state.json`、`events.jsonl`；工件是内容寻址且迁移不修改它们，所以不复制。每个项目保留最近 20 份。
- 迁移事件 `campaign.migrated` 带 `from`、`to`、`backup.sha256` 和治理完整性；它与旧事件在同一条哈希链上。
- `migrate` 幂等：schema 已是 5 时返回 `alreadyCurrent: true`，不写新备份。
- `reindex` 只读 campaign 目录里的 `state.json`，重建 `index.json`；损坏的项目被跳过并报告，不删除任何文件。

## 5. 导出包的证明边界

`BUNDLE.zip` 与独立导出目录新增：

| 文件 | 内容 |
| --- | --- |
| `STEWARDSHIP.md` | 许可、数据/代码可用性、利益冲突、伦理、资助、关键词与 CRediT 表 |
| `MANIFEST.json` | 插件版本、schema、项目 id/seq/lastHash/stateHash、release gate、每个导出文件的大小与 SHA-256 |

`MANIFEST.json` 不能包含自身哈希，也不包含 `BUNDLE.zip` 自身哈希；这是格式约束，不是遗漏。工件不逐个列入清单，因为它们是内容寻址的，完整列表在 `campaign.json`，实际打包项在 ZIP 目录中。验证清单时以 `files[].path` 相对导出目录读取，逐个核对字节数与 SHA-256。

导出的 `campaign.json` 是当时的物化状态，不是事件回放证明；事件证明看 `ledger.jsonl` 和 `MANIFEST.json` 中的 `lastHash`/`stateHash`，以及运行时 `doctor`/`verify`。

## 6. 标准合成

1.0 没有把标准当装饰，而是把每个标准压到一个可检查的数据结构或输出：

| 标准/实践 | 在本套件中的落点 |
| --- | --- |
| PRISMA 2020 | 候选级三阶段决策、PRISMA 计数、Mermaid 流程图、JSON/Markdown/CSV |
| GRADE | `certainty` 分级；证据强弱与不确定性分开记录 |
| Toulmin | `warrant` + `counterEvidence`；证据不能自动等于结论 |
| PROV | `provenance.json`，实体/活动/代理与关系 |
| RO-Crate 1.1 | `ro-crate-metadata.json`，含许可、关键词与可访问条件 |
| FAIR | schema 5 许可、数据/代码可用性、关键词、持久标识（DOI/ORCID） |
| CRediT | 14 个标准贡献角色，替代自由文本“参与了” |
| CSL-JSON / BibTeX / RIS | 参考文献可进可出，Zotero/EndNote 互操作 |
| OpenAlex / Crossref | 实时检索与 DOI 精查，来源文本只作数据、不作指令 |
| W3C PROV / HMAC | 事件链 + 本地签名审计，篡改可检测 |
| 九道闸门 / waiver | 发布前必须通过；例外必须署名、到期、可审计 |
| 复现包 | 精确命令、种子、环境锁、负对照、stdout 校验和 |

## 7. 验收标准

1.0 的验收不是“设计完成”，而是以下全部成立：

- 静态：`npm run release:check` 通过；`npm run check` 的 client bundle 与源码一致。
- 单元/集成：全部测试通过；新增治理、迁移、doctor、manifest、工具/面板/客户端回归测试。
- 端到端：`npm run acceptance` 在临时目录完成 release → export → migrate → reindex，逐一验证 manifest 哈希，输出 `_artifacts/acceptance-1.0.0.json`。
- 真实运行：在已安装的 DSH live panel 上完成 `doctor`、治理写入、导出与显式迁移，保留 API 响应、导出文件和面板截图。
- 稳定性：RSI 确定性夹具与跨领域套件全绿；devkit `verify` 与 `trend` 无回归、无 flaky、耗时漂移在可解释范围内。

## 8. 已知边界

- 不抓取或解析 PDF；全文决策仍由研究者/agent 提供。
- 不做双人独立筛选与 kappa；PRISMA 计数完整不等于系统综述方法学合规。
- 不自动判断研究质量或伦理批准；`complete` 只表示没有未处理/矛盾的记录。
- 没有静态加密；本地数据目录的访问控制由宿主机负责。
- 没有远端多用户服务；面板固定回环地址。
- 迁移备份只含 state + 事件，不含工件；需要完整快照时用 `export` 生成 `BUNDLE.zip`。
