# 研究程序：从九道闸门到可复核的自主循环（0.8.0）

0.7 让“检索过什么、换设定后是否稳健”变成记录。0.8 处理另一个常被一句“多智能体在跑”带过的缺口：**一个长期研究程序到底计划了什么、从哪些视角看、在什么条件下停、假设之间如何比较、质量由谁按什么标准评分、冲突证据如何处置。**

本文件说明 0.8 的设计来源、状态模型、闸门位置、可复现验收与边界。它不是“已实现全自主科研”的声明；套件仍然不运行检索、不调用模型、不生成实验代码。它把外部代理已经做过的事变成可检查的状态。

## 2. 状态模型

新增一个 `rsx_program` 工具，九个动作，写入以下状态：

| 状态 | ID | 字段 |
| --- | --- | --- |
| `plan` | `G-0001…` | `objective`，`questions[]`：`question`、`priority`(high/medium/low)、`owner`、`status`(open/active/answered/abandoned)、`coverage[]`（必须是本项目的 `S-` 来源） |
| `perspectives` | `O-0001…` | `name`、`stakeholder`、`question`、`sources[]`（`S-`） |
| `autonomy` | 单对象 | `maxCycles`(1–50)、`stopCriteria`、`escalation`、`humanCheckpoints`、`owner` |
| `cycles` | `K-0001…` | `goal`、`step`、`observation`、`decision`(continue/revise/stop/escalate)、可选 `question`(`G-`)、可选 `run`(`R-`) |
| `tournament.matches` | `T-0001…` | `a`、`b`（不同 claim，至少一个 `hypothesis`）、`winner`(a/b/draw)、`criterion` |
| `quality.rows` | `Y-0001…` | `reviewer`、`scores`（六维 0–1）、`overall`（均值）、`minimum`、`scope` |
| `contradictions` | `D-0001…` | `claim`、`evidenceA`、`evidenceB`（`E-`/`S-`/`R-`/`sha256:`）、`status`(open/resolved/explained)、`resolution`（非 open 时 ≥12 字） |

`cycles` 受 `autonomy.maxCycles` 约束：超过预算时服务直接拒绝，而不是静默多跑一轮。要提高预算必须显式改策略，这会留下事件。

## 3. 程序完整性检查

`lib/program.js` 的 `programChecks(state)` 返回十个独立检查：

- `plan_objective`：目标 ≥12 字。
- `plan_questions`：至少 2 个非 abandoned 问题。
- `plan_coverage`：每个 high/medium 问题至少一个能解析到来源的 `coverage`。
- `perspectives`：至少 2 个视角。
- `perspective_sources`：每个视角至少一个能解析的来源。
- `autonomy_policy`：`maxCycles` + `stopCriteria` + `escalation` + `humanCheckpoints` 全齐。
- `cycle_log`：至少一条 act→observe→decide。
- `hypothesis_competition`：至少一个 hypothesis、一个竞争 claim、一场记录在案的 match。
- `quality_rubric`：最新 rubric 六维齐全且 `overall ≥ 0.7`。
- `contradictions_resolved`：没有 open 矛盾。

**闸门位置**：schema-4 项目在 `review` 闸门增加 `program_complete`（blocking）；schema 1–3 项目只作 advisory，保持升级不追溯阻断。审计增加一条 `program_incomplete`（major），列出缺失检查；它不会单独阻断，review 闸门的 `program_complete` 才是硬检查。

**评分语义**：Elo 只是对记录下来的两两判断做确定性累计（K=32，初始 1000，draw 记 0.5）。它不证明胜者真实，也不替代证据；`rank` 返回当前排序和领导 claim。质量 rubric 的六维沿用 Anthropic 的评测词汇：事实准确性、引用准确性、完整性、来源质量、工具效率，加上套件自己的局限与风险。分数是评审者填写的判断，不是模型自动打分。

## 4. 与既有层的关系

- `rsx_program` 是第 15 个工具；它不改九阶段顺序，也不替代 `rsx_claim`/`rsx_evidence`/`rsx_run`。
- 新增状态进入 `auditSubject` 的 `version:3` 分支，只在任一程序字段非空时纳入；旧项目（schema 1–3 且无程序字段）的对象哈希不变。
- 导出新增 `PROGRAM.md`，`REPORT.md` 增加 `3.2 研究计划与视角`、`4.2 假设锦标赛、质量评分与矛盾台账`；验收 `BUNDLE.zip` 30 条目 / 194,971 B，包含 `PROGRAM.md`。
- 闭环评分从 12 维变为 13 维，新增 `program`（权重 8）。schema 1–3 项目该维只返回一条 advisory，不改变旧项目分数；schema-4 项目逐项计分。
- 面板总览增加“研究程序”计数（计划问题 + 视角 + 循环 + 比赛 + 质量行 + 矛盾行）。

## 6. 边界与剩余缺口

- **不是自主科研系统**：没有检索、PDF 解析、模型调用、代码执行或实验设计代理；这些仍由外部 agent/工具完成。
- **不是科学质量证明**：`program_complete` 只证明程序记录齐全，不证明问题值得研究、结论真实或实验有效。
- **Elo 不是统计排名**：一场比赛只能改变记录顺序，不能估计置信区间；比赛标准由人填写，可能被操纵。
- **rubric 不是自动评分**：分数由评审者填写，套件只检查维度齐全与总分阈值；它不能防止评审者偏袒。
- **矛盾台账不是语义检测**：需要人工登记冲突证据并给出处置；PaperQA2 式自动矛盾发现未实现。
- **自主循环不是无限循环**：`maxCycles` 是硬预算，超过即拒绝；这是工程约束，不是对长时自主性的效果声明。
- **schema-4 程序检查只在 review 硬阻断**：早期阶段只记录、不提前卡住；如果你希望更早发现缺口，用 `action:"list"` 随时查看 `complete.missing`。
- **验收是确定性工程夹具**：六案例探针只检验闸门行为，不估计真实科研产出、召回率或统计敏感性；外部来源是设计背景，不是本套件的处理效应。
