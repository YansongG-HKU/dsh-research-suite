# 研究闭环 0.6.0：证据之后，推理与治理

0.5 的闭环解决了“有没有记录”：来源、断言、证据、运行、数字、预注册、领域字段、监测。0.6 补的是记录之后最容易失真的三件事：

1. **证据为什么支持结论**（warrant / counter-evidence / certainty）
2. **多条证据是不是独立**（independence / lineage / risk of bias）
3. **谁批准了发布、批准在什么条件下失效**（approval / waiver / contribution matrix）

这三件事如果只写在提示词里，模型可以绕过；写进状态并用闸门检查，才会在 `advance` 时挡住。

---

## 1. 断言严谨性

`rsx_claim` 新增：

| 字段 | 含义 | 检查 |
| --- | --- | --- |
| `warrant` | 证据通过什么规则支持结论（Toulmin warrant） | 假设/定论缺失 → `hypothesis_warrant` / `claim_warrant` |
| `counterEvidence` | 反向证据检索记录，包含“未发现反例” | 缺失 → `claim_counter_evidence` |
| `certainty` | 证据体的 GRADE 式确定性：high/moderate/low/very-low | 缺失 → `claim_certainty`（minor） |

`claimRigor(claim, evidence)` 还检查：

- 标为 `supported` 但有 `refutes` 证据 → `claim_contested_ignored`，应先改为 `contested` 或说明反证为何不成立。
- 标为定论却没有任何 `supports` → `claim_without_support`。
- 假设本身没有 `warrant` → `hypothesis_warrant`。

schema 2 的 hypothesis/analyze 闸门把这些作为 blocking；schema 1 项目降为 advisory，审计里仍会出现 major/minor。

---

## 2. 来源不是越多越独立

`rsx_source` 新增：

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `independence` | independent / derived / same-group / unknown | survey 要求至少 2 条 independent 的 primary |
| `design` | RCT / cohort / DOE / in-vitro / benchmark … | 判断偏倚风险的上下文 |
| `riskOfBias` | low / some-concerns / high / not-assessed | primary 未评估 → survey 阻断（schema 2） |
| `robNote` | 具体理由与影响方向 | high/some-concerns 必填 |
| `lineage` | `{derivedFrom, relation, note}` | 派生来源必须指向台账里的原始来源 |
| `capturedAt` / `captureMethod` | 捕获时间与方式 | 有正文哈希却无回执 → 审计 minor |

审计会直接指出“八条同源新闻不是八条独立验证”；派生来源找不到原始来源是 major，不是信息提示。

---

## 3. 预注册可锁定、可修订、不可静默改

`rsx_campaign action:"prereg"` 现在保存：

```json
{
  "lockedAt": "…",
  "lockedHash": "…",
  "hash": "…",
  "amendments": [
    { "at": "…", "reason": "样本量计算修正…", "from": "…", "to": "…" }
  ],
  "alpha": "0.05",
  "power": "0.80",
  "effectSize": "…",
  "test": "…"
}
```

规则：

- 首次写入：`hash === lockedHash`。
- 锁定后改核心字段（metric/n/analysisPlan/stoppingRule/seed/controls/envLock/stats）而不传 `amend:true` → `prereg_locked`，不写入。
- 传 `amend:true` 但 `reason` <12 字 → `invalid_input`。
- 合法修订保留 `lockedHash`，更新 `hash`，追加一条 amendment。
- 审计：未修订的漂移是 `prereg_drift`（major），带理由的修订是 `prereg_amended`（info）；成功运行早于 `lockedAt` 是 `prereg_after_execution`（major）。

这不能阻止事后改协议，但能让“事后说明”和“事先预注册”在记录上分开。

## 4. 评审包与词面筛查

`rsx_review action:"packet"` 生成 `REVIEW_PACKET.md`，包含：

- 每条断言的状态、warrant、counterEvidence、certainty、支持/反驳计数与缺口；
- 来源的独立性、设计、偏倚风险、是否被稿件引用；
- 数字的 trace、运行的命令/种子/指标；
- 最近一次审计与完整性摘要；
- 十个评审必答问题。

`action:"entailment"` 是可复现的词面筛查，不是语义蕴含：

- 对每个 supports 证据，取引文与断言的中文 bigram / 英文词元；
- 计算“引文词元中有多少能在断言里找到”；
- 低于阈值（默认 0.2）或引文少于 3 个词元 → `weak`；
- 运行/工件证据标记为 `numeric`，不参与词面比较。

审计把单条弱引文列为 minor，把“所有支持证据都弱”列为 major（`claim_evidence_untraceable`）。它抓的是复制粘贴错位、引文与断言无关、没有引文；它抓不到“用同样的词表达相反意思”。

---

## 5. 可执行复现包

`rsx_write action:"repro"` 或 `export` 写出：

- `REPRO.md`：每条成功运行的命令、种子、期望指标、stdout 工件；预注册参数；校验和。
- `repro.json`：同一份 manifest，供脚本读取。
- `checksums.txt`：内容寻址工件清单。

manifest 明确：期望指标来自已记录的运行，不要为了让重跑结果匹配而改 manifest。负对照单独列出；没有负对照的运行不会被当成负对照。

## 6. 发布治理

### 人工批准

```text
rsx_gate action:"approve" approver:"YG" role:"human-reviewer"
  statement:"已核对证据、复现包与局限，批准发布该版本。"
```

- `subjectHash` 绑定当前审查对象；来源/断言/证据/数字/预注册/领域数据变化后，`approvalFresh` 变 false。
- release 闸门（schema 2）要求最新批准 fresh；审计给 `approval_stale` major。
- `approver` 不能等于声明的模型名；这只是字符串校验，不是身份认证。

### 结构化 waiver

```text
rsx_gate action:"waive" code:"world_question"
  reason:"本次为内部预研，先用外部问题陈述替代世界模型记录。"
  approvedBy:"YG" expiresAt:"2026-12-31"
```

- 理由 ≥20 字、批准人、到期日缺一不可。
- 保护名单：`chain_integrity`、`automated_audit`、`two_reviews`、`adversarial_review`、`declaration*`、`dual_use`、`no_reject`、`claims_resolved`、`no_contested_claims`、`human_approval`、`upstream_gates`、`waiver_hygiene`。
- 生效中的 waiver 会出现在 gate 结果的 `waived` 列表与审计 info 中；到期后重新阻断。
- waiver 不是安全控制，只是把“这次为什么放行”变成可审计记录。

### AI/人类贡献矩阵

`declaration.contributions` 默认生成一条 AI（分析/代码/初稿）和一条人类（评审/批准），导出 `AI_CONTRIBUTION.md`。schema 2 release 要求两类角色都存在。它记录分工，不转移责任：人类批准者仍对发布结论负责。

## 7. 组合视图与跨领域回归

- `rsx_campaign action:"portfolio"`：跨项目分数、等级、阶段、审计新鲜度、告警数、覆盖缺口、完整性、token 花费。
- 领域标准带 `status` / `reviewedAt`；`DOMAIN.md` 显示复核日期，避免把过期清单当成当前标准。
- `action:"graph"`：claim 的 parent、evidence 的 supports/refutes/context、source lineage、number trace、figure produced-by/data 边。
- `npm run rsi:suite`：通用 + 四个领域各跑一次九阶段，输出 `_artifacts/rsi-suite.{json,md}`。失败按命名检查报告，不是只报一个总分。

---

## 8. 兼容与迁移

- 新建项目 `state.schema = 2`，新检查按阶段 blocking。
- 0.5 及更早项目 `schema` 缺失/为 1，新检查为 advisory；审计仍会给 major/minor，但不阻断已发布项目。
- 旧项目补字段后，`rsx_gate action:"check"` 会显示哪些 advisory 已满足；是否显式迁移到 schema 2 需要单独决定，不能因为分数 100 就假设已经具备所有新字段。
- 真实项目 `rs-ad07b91f` 是 schema 1：补 warrant/独立性/批准后达到 100/L4，但它的新检查仍是 advisory；这一点在 README 验收与 `real-acceptance-0.6.json` 中明确记录。

---

## 9. 边界

- entailment 是词面筛查，不是语义判断。
- 批准与 waiver 的批准人是声明字段，不是 SSO 身份。
- waiver 不能关闭完整性/签名/独立性/声明/上游闸门/人工批准类检查。
- 分数只衡量工程可复核性，不判断科学结论、临床有效性、法律合规或投资建议。
- 真实焊接项目的数据是合成夹具；`riskOfBias:"high"` 与 `certainty:"low"` 是对此的诚实标注，不是焊接物理结论。
