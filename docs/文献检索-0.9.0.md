# 文献检索执行层（0.9.0）

0.8 的研究程序能记录“计划了什么、从哪些视角看、何时停”，但检索本身仍由 agent 在套件外完成，再手工登记。0.9 的第一步把检索变成宿主侧可执行能力：`rsx_search` 直接查询 OpenAlex 与 Crossref，返回规范化、去重、带来源标记的候选。

它只解决“找到并核对题录元数据”，不解决“全文获取、语义筛选、自动写入台账”。后者仍由 agent 阅读后显式登记，保持“读过才引用”的边界。

## 1. 目标与验收

目标：一次调用可以同时查两个公共元数据源；任一源失败不拖垮整体；DOI 大小写与 URL 前缀归一；同一 DOI 的跨源记录合并；所有外部文本有长度上限并清理标记。

验收：

- 离线测试覆盖成功、跨源去重、单源失败回退、双源失败、超时、坏 JSON/坏结构、参数校验、年份过滤，共 12 个用例。
- 真实网络验收同时命中 OpenAlex 与 Crossref，至少 3 条候选、至少 3 个 DOI、至少 1 条跨源合并、无 warning，并验证 Crossref 单源回退。
- 全量测试、`npm run check`、`npm run rsi`、`npm run rsi:suite` 与 devkit 闸门全绿。
- 不引入运行时 npm 依赖；不改变九道闸门与 profile。

## 2. 接口

```json
{
  "query": "multi-agent research system",
  "provider": "both",
  "limit": 6,
  "yearFrom": 2020,
  "yearTo": 2026,
  "timeoutMs": 12000
}
```

`provider` 可为 `both`（默认）、`openalex`、`crossref`。`limit` 为合并后的上限，1–20；每个源按同一上限请求。`timeoutMs` 是**单源**超时，1–15 秒，默认 8 秒。工具整体超时 40 秒。

返回：

```json
{
  "ok": true,
  "query": "…",
  "provider": "both",
  "providers": ["openalex", "crossref"],
  "counts": { "openalex": 6, "crossref": 6 },
  "candidates": [
    {
      "title": "…",
      "year": 2026,
      "doi": "10.26434/chemrxiv.15005228/v1",
      "url": "https://doi.org/10.26434/chemrxiv.15005228/v1",
      "authors": ["…"],
      "venue": "ChemRxiv",
      "abstract": "…",
      "citations": 0,
      "kind": "paper",
      "provider": "openalex",
      "providers": ["openalex", "crossref"],
      "providerIds": { "openalex": "https://openalex.org/W…", "crossref": "10.26434/…" }
    }
  ],
  "warnings": [],
  "elapsedMs": 3794
}
```

单源失败时 `warnings` 形如 `{provider, code, message}`，仍返回另一源结果；两个源都失败才抛 `retrieval_failed`，单源超时抛 `retrieval_timeout`。工具层把异常包成 `{ok:false, code, error, repair, detail}`。

## 3. 规范化

- DOI：去掉 `https://doi.org/` 与 `doi:` 前缀、去尾部标点、统一小写；合并键为 `doi:<规范化 DOI>`；无 DOI 时用 `title:<规范化标题>|<year>`。
- 标题/摘要/作者/期刊：去 HTML/JATS 标记、解码常用实体、压缩空白；标题最多 400 字符、摘要最多 2,000 字符、作者最多 12 人。
- OpenAlex 的 `abstract_inverted_index` 按位置重建为摘要；Crossref 的 JATS 摘要去标记。
- 类型映射到套件已有的 `paper/preprint/dataset/book/report/other`。
- 同 DOI 合并时保留首个顺序，用后出现的更完整字段填补摘要、作者、期刊、引用数；`providers` 与 `providerIds` 取并集。
- 年份过滤使用各源原生参数：OpenAlex `from_publication_date`/`to_publication_date`，Crossref `from-pub-date`/`until-pub-date`。

## 4. 安全与边界

- 只发 GET，跟随重定向；单源超时 1–15 秒，双源最坏约 30 秒，工具整体 40 秒上限；单源响应上限 4 MB，超限或非 JSON 直接报错；不提交表单、不带凭据、不下载全文。
- 外部标题/摘要是**数据**，不执行、不作为指令；工具描述明确标注。
- 只读：不写 campaign、事件链、工件或配额；候选必须由 agent 检查后用 `rsx_source` 登记。
- 不做相关性重排；返回顺序是各源相关性顺序合并后的结果。去重不等于语义等价，预印本 v1/v2 会保留为不同 DOI。
- 不保证覆盖数据库全集；OpenAlex/Crossref 的收录范围、延迟与速率限制由上游决定。生产批量检索应使用 `searchLog` 记录协议并遵守各源条款。
- 不做 PDF 解析、不做全文核验；`rsx_review` 的引文检查仍只针对已捕获正文。

## 5. 测试与真实验收

离线 12 个用例在 `test/unit/retrieval.test.mjs`，工具分派与错误映射在 `test/unit/tools.test.mjs`。全量 **122/122** 通过。

真实网络验收脚本：`_artifacts/real-0.9/run-search.mjs`。2026-11-17 结果：

- 主查询 `multi-agent research system`：OpenAlex 6 条 + Crossref 6 条，合并后 6 条候选，3,794 ms，0 warning。
- 跨源合并 2 条（GVIM 2.0 的 v1/v2 均同时出现在两个源）；DOI 唯一；候选均带标题。
- 回退查询 `sleep deprivation working memory`，`provider:"crossref"`：3 条，340 ms，0 warning。
- 宿主会话：插件禁用/启用后，当前 DSH 会话直接调用 `rsx_search` 查询 `reproducibility crisis psychology`，OpenAlex 3 + Crossref 3、合并 3 条、1 条跨源合并、0 warning、2,606 ms；最终 bundle 重载后再查 `open science reproducibility`，2 + 2、0 warning、3,442 ms；候选带摘要与作者，未写台账。空查询在宿主返回结构化 `invalid_input`，没有发网络请求。
- 12 项检查全部 PASS，`search-live.json` 与 `search-live.log` 为原始证据；工具 handler、宿主调用与错误路径分别在 `tool-call.json`、`host-tool-call.json`、`host-tool-call-final.json`、`host-invalid-call.json`。

这不是召回率或查全率评估，只是“真实 API 可达、双源合并、失败可回退、结果可规范化”的工程验收。

## 6. token 开销

`npm run measure` 快照 16 个 schema 与系统提示：**11,422 cl100k / 11,390 o200k**，其中提示词 940/925、`rsx_search` schema 372/372。相对 0.8 的 11,002/10,969 增加 **420/421**（约 +3.8%）。不做科研时可在插件管家禁用整个 bundle，固定开销归零。
