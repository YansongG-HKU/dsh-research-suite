# 研究闭环 0.5.0：条件适用性、监测判定、独立评审与 RSI 门槛

0.4.0 解决了“领域协议能不能变成阻断检查”。0.5.0 解决四个更接近闭环的问题：

1. **不是所有字段都永远适用**：研究设计、风险等级和报告类型变化时，字段与标准要跟着失效，而不是靠一条 `N/A` 掩盖。
2. **监测计划不等于监测**：必须能登记指标、记录观测、按目标/容差判定，并在越界时真正触发回退。
3. **角色字符串不等于独立评审**：评审人要有机构/身份、利益冲突声明和独立性；同一人不能同时覆盖两个角色。
4. **闭环要有可比较的分数**：12 个工程维度、版本化基线、候选改动重跑与回归门槛，形成可重复的自我改进循环。

它是工程可复核性评分，不是论文正确性、临床有效性、法律合规或智能水平测量。

## 1. 条件适用性

`lib/domains.js` 的字段和标准现在可以带 `when`：

```js
text('search_strategy', 'survey', '检索策略与日期', 'Search strategy and dates', {
  min: 20,
  when: { field: 'study_design', in: ['systematic-review', 'meta-analysis'] },
  whenNote: '仅系统综述/元分析适用',
})
```

支持的条件形式：

| 形式 | 含义 |
| --- | --- |
| `{field, in: [...]}` | 值在集合内才适用 |
| `{field, notIn: [...]}` | 值不在集合内才适用 |
| `{field, equals: value}` | 精确匹配 |
| `{field, present: true/false}` | 有值/无值时适用 |
| `{all: [...]}` / `{any: [...]}` | 条件组合 |

行为：

- `fieldApplicability(field, state)` 返回 `{applicable, reason}`；无 `state` 时保持旧行为（适用），供纯校验使用。
- `domainMissing`、`domainCompleteness`、`domainChecks`、`domainGateSummary`、`renderDomainMarkdown` 全部按当前状态过滤。
- 条件不满足的字段不要求填写，也不产生 blocking；已存在的旧值保留，但不会误判为满足/不满足。
- 跨字段规则（PRISMA 计数、OOS 日期）在任一相关字段不适用时跳过。
- 标准条目也可以带 `when`；`DOMAIN.md` 显示“适用”或“参考：原因”，而不是把所有标准都当成强制要求。

当前条件示例：

| 档案 | 条件字段 | 触发条件 |
| --- | --- | --- |
| medicine | `search_strategy`、`databases`、`screening`、`prisma_*` | `study_design` ∈ 系统综述/元分析 |
| medicine | `randomization`、`blinding` | `study_design = rct` |
| industrial | `factors`、`levels`、`randomization` | `design_type` ∈ DOE/全因子/部分因子/响应面 |
| industrial | `replicates` | 上述 DOE 或 `reliability` |
| ai | EU AI Act 标准条目 | `risk_tier` ∈ limited/high |

## 2. 监测从“计划”变成“判定”

`lib/monitor.js` 是纯函数模块，不抓取任何外部遥测。观测由操作者/集成显式登记，所有登记都进入事件链。

监测数据结构：

```jsonc
{
  "status": "planned|active|paused|closed|alert",
  "plan": "……",
  "owner": "……",
  "cadence": "weekly",
  "signals": ["accuracy", "defect_rate"],
  "metrics": [
    { "name": "accuracy", "target": 0.9, "tolerance": 0.02, "direction": "higher", "min": 0.85 }
  ],
  "observations": [
    { "metric": "accuracy", "value": 0.95, "at": "2026-01-01T00:00:00.000Z", "note": "……" }
  ],
  "reviewedAt": "……"
}
```

判定规则：

- 每个指标取**最新**观测；`higher` 看下限（target − tolerance），`lower` 看上限（target + tolerance），`two-sided` 看绝对偏差；`min`/`max` 是硬边界。
- 越界产生 `metric_out_of_tolerance` 告警；`status` 变为 `alert`。
- 已登记信号没有指标、已登记指标没有观测、观测没有对应指标，分别产生 `signal_without_metric`、`metric_without_observation`、`observation_without_metric` 缺口。
- 缺口不是告警，不会把刚建立的监测计划直接判失败；但**闭环评分**会检查覆盖，避免“计划里有信号、实际上没人量”。
- 告警会进入 `REPORT.md` / `DOMAIN.md` / `LOOP.md`，并写入 `monitoring.alert` 事件。
- `rsx_campaign action:"monitor"` 支持 `metrics`、`observations`、`reopen:true`、`reason`；`reopen` 把已发布项目退回 `analyze`，写入 `loop.reopened` 事件，之后要重新走 write → review → release。
- 发布闸门仍只要求计划/负责人/频率/无告警；指标覆盖属于闭环质量，不强行把旧项目升级为失败。

## 3. 独立评审与利益冲突

0.5 的新评审记录带 `schema: 2`：

```jsonc
{
  "reviewer": "……",
  "affiliation": "独立统计评审组",
  "conflict": "none",
  "independent": true,
  "qualification": "……",
  "role": "clinical",
  "adversarial": false,
  "verdict": "minor",
  "issues": []
}
```

规则：

- 领域角色评审必须满足：姓名非匿名、`affiliation` 至少 2 字、`conflict` 至少 2 字、`independent !== false`。
- 同一评审人不能同时覆盖两个领域角色；出现重复姓名会生成 `domain_<profile>_review_independence` blocking。
- 旧版评审（没有 `schema` 或 `schema < 2`）保持兼容，不会被升级动作凭空判失败；审计和报告会把它标为“旧版记录”。
- `rsx_gate action:"review"` 新增 `affiliation`、`conflict`、`independent`、`qualification` 字段；`REPORT.md` 第 8 节显示角色、独立性、机构/COI 与未解决 blocking。

这是**声明与结构检查**，不是身份验证或 COI 调查；工具只检查声明是否存在、角色是否由不同人覆盖。

## 4. 12 维研究闭环评估

`lib/loop.js` 对当前项目计算 0–100 的工程成熟度。每个维度有固定权重，维度分 = 通过检查数 / 总检查数，总分 = 加权平均 × 100。

| 维度 | 权重 | 检查重点 |
| --- | ---: | --- |
| 问题与边界 | 6 | 问题、边界、成功判据、世界模型问题、领域 scoping |
| 证据测绘 | 10 | 8 来源、2 一手、近期 1、正文捕获、否证检索、覆盖域、抽取矩阵 |
| 可证伪假设 | 10 | falsifier、killCriterion、预测、指标/单位、2 条支持、查新、状态已定 |
| 预注册设计 | 7 | 预注册、假设关联、主指标、n、分析计划、停止规则、种子、负对照、环境锁 |
| 可复现执行 | 13 | 成功运行、种子、指标、负对照、命令、stdout 工件、运行历史 |
| 数字与引文追溯 | 10 | 数字登记、trace、trace 可解析、引用存在、引用可解析、图完整、工件角色、链完整 |
| 自动化审计 | 10 | 审计存在、对象哈希新鲜、HMAC 验签、无 blocking、stateHash |
| 独立评审 | 9 | 两份评审、对抗评审、无 reject、无未解决 blocking、两位独立评审人、身份/COI、领域角色 |
| 领域适用性 | 7 | 档案、适用字段、完成度、阶段检查、适用标准 |
| 发布后监测 | 8 | 计划、负责人、频率、指标、观测、无告警、无覆盖缺口、复查时间 |
| 发布声明 | 6 | release、AI 声明、水印、人工复核人、dual-use、release 闸门 |
| 台账完整性 | 4 | 事件链、stateHash、工件异常、事件数 |

等级：

| 分数 | 等级 |
| ---: | --- |
| ≥90 且监测满分、评审 ≥80% | L4 可审计闭环 |
| ≥78 | L3 可复核研究 |
| ≥55 | L2 证据化草稿 |
| >0 | L1 立项 |
| 0 | L0 空白 |

自我改进前提（`rsi.prerequisites`）：

1. 新鲜、验签通过、无 blocking 的自动审计；
2. 两名独立评审人，领域项目覆盖两个角色；
3. 监测有指标、有观测、无未处理告警，且每个信号都有指标覆盖；
4. 闭环成熟度 ≥85。

这些是**可以开始比较候选改动**的工程前提，不代表系统能自主修改自己，也不代表结论正确。候选改动必须在同一评估器上重跑，并与版本化基线比较。

### 记录与导出

```text
rsx_campaign action:"evaluate"
  → 返回 evaluation，写入 state.loopBaseline（首次）、state.loopEvaluation、state.loopEvaluations
  → 事件 loop.evaluated

rsx_write action:"export"
  → LOOP.md 进入导出目录与 BUNDLE.zip；REPORT.md 第 19 节渲染同一评估
```

`loopEvaluations` 保留最近 50 次；第二次起带 `previousScore` 与 `delta`。

## 5. RSI 回归门槛

`scripts/rsi-eval.mjs` 通过真实 service API 构建一个确定性的完整项目：

- 九阶段全部推进；
- 一条抽取矩阵；
- 一条真实 stdout 工件；
- 两名带身份/COI 的独立评审；
- 一份通过验签的自动审计；
- 一个带指标与观测的监测计划；
- 计算 12 维评分，写入报告，并与 `_artifacts/rsi-baseline.json` 比较。

```powershell
npm run rsi                         # 与基线比较，分数下降时退出码 1
npm run rsi -- --update-baseline    # 更新基线（需要人工确认）
```

基线是仓库文件，不是运行时状态；任何降低分数的改动都会被 CI/本地门槛挡下。它衡量的是**评估器与流程完整性**，不是模型能力。

0.5.0 的确定性夹具结果：

| 指标 | 值 |
| --- | --- |
| 分数 | **100/100** |
| 等级 | L4 可审计闭环 |
| RSI 前提 | 满足 |
| 基线 | `_artifacts/rsi-baseline.json` |

## 7. 仍未解决的问题

- **监测不是自动采集器**：没有外部遥测接入、SPC 自动计算、告警分级升级或自动回退；观测必须显式登记。
- **评审身份不是验证**：机构/COI 是声明字段，工具不查数据库、不验证签名身份；“独立”是结构约束，不是社会学保证。
- **评分不是正确性**：12 维只检查可复核性；统计方法、临床终点、法律适用性仍由领域评审人负责。
- **审计仍是记录一致性检查**：不重算统计模型、不验证 PRISMA 流程、不验证 GCP 合规。
- **RSI 是门槛不是自治**：没有自动生成/合并改动；候选改动仍需人类审查、测试与发布。
- **领域组合**：AI+medicine 等复合档案尚未实现；当前只能选一个主档案。
- **条件适用性依赖已登记字段**：如果 `study_design` 为空，条件字段默认适用（避免静默漏检）；这要求 scoping 阶段先填设计类型。

## 8. 版本与兼容

- 版本：`0.5.0`（`package.json` / `lib/config.js` / client bundle）。
- 工具数量：仍为 14；新增能力挂在 `rsx_campaign action:"evaluate"`、`rsx_campaign action:"monitor"` 与 `rsx_run action:"attach"`。
- 旧项目：没有 `loopEvaluations` / `monitoring.metrics` 的状态在读取时按空值处理；旧评审没有 `schema` 时按兼容记录处理。首次 `evaluate` 会建立基线，不需要迁移脚本。
- 口径：所有领域内容都是“标准/清单对齐”，不构成认证、法律、临床或投资合规结论。
