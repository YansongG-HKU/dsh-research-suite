# schema-4 研究程序闸门的真实验收

本报告检验 0.8 的研究程序是否真的进入评审闸门。研究在隔离状态中构造六个案例：缺程序、补齐程序、开放矛盾、解释矛盾、低质量评分和 schema-3 负对照 [[src:S-0009]]。外部设计来源包括 Anthropic 的多代理编排与工作流边界 [[src:S-0001]]、Co-Scientist 的锦标赛演化 [[src:S-0003]]、Kosmos 的世界模型与长循环 [[src:S-0004]]、PaperQA2 的矛盾检测 [[src:S-0005]]、STORM 的多视角提问 [[src:S-0006]] 与 AI Scientist-v2 的端到端流程 [[src:S-0007]]。

确认性重跑在预注册锁定之后执行，主指标是阻断案例数 {{N-0001}}。缺程序、开放矛盾和低质量评分三类案例的 review blocking 含 program_complete；补齐程序、解释矛盾与 schema-3 负对照不含。schema-3 负对照说明差异来自版本化契约，而不是“任何缺字段都会阻断” [[src:S-0010]]。

多代理系统确实可能提高广度覆盖，Anthropic 报告 90.2% 的内部评测增益，但也报告约 15 倍于聊天的 token 成本；因此程序层必须同时记录停止条件、升级条件和人类检查点，而不能把“更多代理”当作默认答案。PaperQA2 报告每篇论文约 2.34 个矛盾、70% 经专家验证，这支持把矛盾作为一等对象；本研究仍只验证闸门行为，不验证这些外部效应量。

局限：六个案例是确定性工程夹具，只检验闸门判定，不检验真实科研产出、召回率或统计敏感性；外部来源是设计依据，不是本研究的处理效应；schema-4 的程序完成也不等于结论为真。

结论：在本机插件服务中，计划、视角、自治循环、锦标赛、质量评分和矛盾台账是实际参与 review 判定的状态，而不是只在报告里出现的文档字段。
